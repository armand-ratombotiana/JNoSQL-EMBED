The embedded multi-model NoSQL database for the JVM

JunifyDB packs document, key-value and column-family stores into one tiny embeddable engine — with ACID transactions, full-text and vector search, and a REST API. Think H2 for the NoSQL world.

Document Store

JSON-like documents with rich queries, secondary indexes, aggregation pipelines and TTL.

Quick start

Add one dependency, embed the database, ship.

<dependency>
    <groupId>org.junify.db</groupId>
    <artifactId>junify-db-core</artifactId>
    <version>1.0.0</version>
</dependency>
implementation("org.junify.db:junify-db-core:1.0.0")
var db = JunifyDB.embed()
    .storageEngine("FILE")   // or IN_MEMORY, B_TREE, LSM_TREE
    .persistTo("data")
    .build();

var users = db.documentCollection("users");
var user = new Document();
user.id("user-1");
user.add("name", "Alice");
user.add("age", 30);
users.insert(user);

var adults = users.find(Query.eq("age", 30));
# Start the server
java -jar junify-db-core.jar --port 8080 --engine FILE --data-dir ./data

# Health check
curl http://localhost:8080/api/health

# Create a document
curl -X POST http://localhost:8080/api/collections/users \
    -H "Content-Type: application/json" \
    -d '{"name": "Alice", "email": "alice@example.com"}'

Storage engines

Pick the trade-off per deployment — the API stays the same.

EngineBest forPersistence
IN_MEMORYTests, caches, ephemeral dataNo
FILEGeneral purpose, JSON + WALYes
B_TREESorted indexes, range queriesYes
LSM_TREEWrite-heavy workloads, bloom filterYes

Security & operations built in

  • API-key authentication per endpoint
  • Rate limiting (1000 req/min per IP)
  • CORS + GZIP response compression
  • Real-time metrics stream and health endpoint
